# Design Document: Code Review Remediation

**Author:** Scott A. Idler
**Date:** 2026-06-09
**Status:** In Review
**Review Passes Completed:** 5/5
**Crates touched:** derive, telemetry, store, domain, llm, tools, worktree, ipc, context, decomposer, agents, integrator, loopr

## Summary

A workspace-wide code review (13 parallel reviewers: one per crate, two each for `loopr` and `agents`, one cross-cutting; ~150 deduplicated findings, several confirmed empirically by probe and several re-verified by hand) found 18 critical bugs, ~50 majors, and a long tail of minors/nits. This doc converts every finding into a phased fix plan. Every named finding gets coverage here - nothing is deferred or "tracked separately."

## Problem Statement

### Background

The 2026-06-09 review examined all 13 crates against `docs/vision.md`, the per-crate CLAUDE.md contracts, and the user rules (logging, CLI conventions, test placement, naming). Reviewers were primed with loopr's own failure history: git-vs-DB two-layer state divergence, doom loops, zombie processes, detached spawns, and config-parsed-but-ignored. Two findings were confirmed by running probe code (the `bash -c` denylist bypass, the multibyte truncate panic); the vapor findings (`catch_unwind`, `FailureReason`, budgets, `costs.jsonl`) were re-verified by grep; the headline criticals (force_propose staging, `-C` re-rooting, the 3s kill window, the drain loops, the director cap absence, the pattern-tracker early return) were re-verified by reading the code directly.

Positive findings worth recording: the worktree seq-allocation race-safety, `LC_ALL=C` forcing, and git-stderr-phrase matching all check out clean with regression tests; the integrator's no-LLM Cargo contract holds transitively; mainline scoped staging is solid; all live FSM transition call sites map to real table edges; and four of the five Director Phase-2 known gaps from project memory are fixed in code (Stalled->Active respawn, three-layer retry-budget enforcement, reconcile tests, notify lifecycle - only the detached WorkSpawner shims remain, covered in Phase 7).

### Problem

Five systemic defect classes, plus per-crate bugs:

1. **The vision lies.** Whole subsystems the vision presents as decided-and-built do not exist: the panic posture (`catch_unwind` everywhere, `FailureReason::Panic`) has zero implementation; budgets, `DaemonEvent::BudgetExceeded`, and `.loopr/costs.jsonl` are vapor; model tier resolution exists nowhere; commit trailers and signing are absent (every agent commit passes `--no-gpg-sign`); the 5-layer config chain is a target file plus one env var; the `DaemonEvent` bus is subscribed but never sent to. Contract docs (crate map edges, ABI signatures, CLAUDE.md scope lists) are wrong on a dozen counts. An implementer - human or agent - following the docs builds on fiction.
2. **Two-layer state divergence, the v3/v4 killer, is structurally present.** Plan updates have no OCC and three concurrent writers (Reactor, Director, IPC override); the Work/Bundle OCC token is wall-clock-ms equality defeated by same-millisecond writes; the integrator has three crash/timeout windows where git advances and the DB doesn't (or vice versa); `override_work` spawns an Implementer off locally-mutated state after a failed persist.
3. **Containment is fail-open.** The Bash denylist is bypassed by `bash -c "<denied>"`, absolute paths, and `rm` flag variants (all empirically confirmed); Bash itself never runs under bwrap (the vision's "bwrap contains it" is false - in practice bwrap wraps only `grep`); target-repo content escapes its code fences into reviewer/implementer prompts (forged-verdict injection); the per-Work `files` scope is never rendered into any prompt (agents are ordered to respect a list they cannot see, under a field name - `resource_tags` - that no longer exists), is unvalidated at decompose time, and is bypassed entirely by `force_propose`.
4. **Doom-loop brakes are incomplete exactly where they're expensive.** The Director (Opus, long-lived) has no iteration/wall-clock/cost cap; its pattern tracker's SameAction branch starves the escalation path forever (the common doom loop never reaches NeedsOperator) while idle `done` iterations false-positive into a Conservative-mode trap with no exit; rejected-bundle feedback never reaches retry implementers; two of three advertised v4 safety-net counters are dead (`bundle_rejections` doesn't exist, `session_failure_count` is never written); decomposer validation errors never get the self-correct retry the machinery was built for and instead stall the Plan permanently - and the documented recovery (`plan override --to active`) is a dead end that neither re-decomposes nor respawns a Director.
5. **Silent death.** All six pipeline JoinSets swallow task panics (daemon stdio at `/dev/null`, no panic hook - a panicking Implementer strands its Work with zero log evidence); `daemon stop` SIGKILLs after 3s against a ~2.5min drain budget; telemetry fanout failures are swallowed per-event forever; LLM usage on error-classified responses (the expensive failures) never reaches the cost counters.

### Goals

- Fix all 18 criticals with regression tests in the same change.
- Eliminate the five systemic classes, not just their instances.
- Make every doc/contract (vision.md, crate CLAUDE.md files, roadmap, design docs) tell the truth - implement the claim or amend the doc, never leave the contradiction.
- Bring rule-drift up to the user's own rules (CLI case-insensitivity, tests in sibling files, no `#[allow(dead_code)]`, banned `dirs::` calls, dep hoisting).
- Close every test gap the review identified.

### Non-Goals

- New features beyond what the vision already promises (no TUI, no researcher, no multi-level hierarchy, no AutoResearch harness).
- Multi-bundle integration GA (`allow_multi_bundle` stays `false`; Phase 2 fixes the re-entry bugs that must precede any flip).
- Re-litigating settled architecture (typed seams, reactive daemon, flat-interior worktrees, NDJSON framing).
- Performance work beyond the specific findings.

## Proposed Solution

### Overview

Eleven phases ordered by severity and dependency: agent-pipeline correctness first (the bundle/staging bugs corrupt the core loop today), then integrator git-state integrity, OCC/FSM state integrity, doom-loop brakes + panic posture, containment, cost accounting + budgets, daemon lifecycle, CLI/init, cross-crate hygiene, doc truth, and test-gap closure. Every fix lands with its regression test in the same phase. `otto ci` gates every phase.

### Architecture

No new crates. The structural additions, all inside existing crates:

- `domain::FailureReason` - the typed failure enum the vision already specifies (`TokenBudget`, `ToolFailure { tool }`, `ReviewerRejection`, `AcUnmet`, `Panic`, `CrashInterrupted`, `Other(String)`), carried on `Work`/`Bundle` with a companion `error: String`.
- `store::PlansStore` gains the same OCC + update-lock shape as Works/Bundles; all three stores gain a monotonic `updated_at` floor (`max(now_millis(), current + 1)`) protecting both OCC and the taskstore merge driver from same-ms ties.
- `llm::RetryableReason` enum (`RateLimited { retry_after }`, `Overloaded`, `ServerError`, `Network`, `MalformedBody`) replacing the bare `Retryable { reason: String }`; `LlmError` variants carry `Usage` so billed-but-failed calls are countable.
- A `models:` tier table in config (`primary`/`lightweight`/`advisor`) with resolution in `llm`, per the vision's ABI; per-run cost cap checked at the daemon's spawn gates; `MeteredLlmClient` appends `.loopr/costs.jsonl`.
- `tools::denylist` recurses into `sh|bash|zsh -c` payloads, normalizes argv[0] paths, and matches `rm` structurally (any r+f flag combination against `/`, `/*`, `~`, `$HOME`).
- `context` gains dynamic fencing (longest-backtick-run + 1) with untrusted-data labels for every interpolation of repo/LLM/operator content, a `section-ac` SSOT partial, and Work-scope (`files`) rendering for implementer and reviewer.

### Data Model

- `Work`/`Bundle` gain `failure_reason: Option<FailureReason>` (serde `default`, additive - old JSONL rows deserialize clean).
- `Work.session_failure_count` becomes live (incremented on implementer escalation/error) or is deleted along with its vision claim - decision: **live**, it is one of the three advertised safety nets.
- `.loopr/costs.jsonl`: append-only, one line per LLM call (`ts`, `plan_id`, `work_id`, `role`, `model`, `input_tokens`, `output_tokens`, `cost_usd`), exactly the vision's shape.
- Work IDs stay 5-char base36, but `WorksStore::create_many` pre-checks incoming ids against the store and returns `AlreadyExists` on collision; the plan-create handler re-mints the colliding ids (remapping the freshly-built dependency edges, which reference ids it just minted) and retries the persist. Re-minting cannot live inside `create_many` - the store doesn't know about the dependency map.

### API Design

- `decompose` validation errors (`DuplicateTitles`, `ZeroChildren`, `EmptyTitle`, `UnresolvedDeps`, `CycleDetected`, `EmptyAcceptanceCriteria`, `MalformedChildren`) route through the existing retry-with-error-in-prompt once before bailing - the behavior every doc already claims.
- `ipc` gains `DaemonEvent::Error { plan_id, work_id, reason, message }` emission from the daemon's terminal/Blocked transition paths and `DaemonEvent::BudgetExceeded` - the bus exists; it just needs senders.
- `loopr plan override --to <status>` becomes a clap `ValueEnum` with `ignore_case = true`; `--output` gains `ignore_case = true` (both are hard CLI-rule violations today).
- `Stalled -> Active` override re-enters `decompose_and_dispatch` when the Plan has zero Works, and (already shipped) respawns a Director - closing the documented dead-end recovery path.
- `worktree::delete_branch` rejects non-`loopr/`-prefixed branches with the already-defined-but-never-constructed `InvalidBranchName`; `cleanup_at` validates the path is under `.loopr/worktrees/`.

#### Phase 2: Integrator git-state integrity
**Model:** opus

- [ ] `integrator/src/git.rs:275` - `run_git` wraps `cmd.output()` in a timeout but never sets `kill_on_drop(true)` (contrast validation.rs:49); a timed-out `git merge`/`checkout` keeps running and can land its mutation AFTER `integrate` returned `Err` - git advances, DB records nothing, the retry races the orphan. Fix: `kill_on_drop(true)`; route merge-side infrastructure errors through `fail_all` instead of the bare `?` at lib.rs:353.
- [ ] `integrator/src/lib.rs:281` - daemon crash in the conflict window (conflicted index + `MERGE_HEAD` on disk) wedges integration permanently: re-entry fails at `checkout` ("resolve your current index first") and nothing ever runs `merge --abort` (the existing `merge_abort` calls at lib.rs:358/605 sit after the failing checkout). - [ ] `integrator/src/lib.rs:395` - validation failure after an `AdoptedExisting` re-entry rolls back to a `pre_merge` captured AFTER the prior crash's merge landed: merged commits stay on the integration branch while the Bundle is terminally `IntegrationFailed` (possibly with a persisted Tick referencing it). Fix: skip the rollback-and-fail path when all outcomes are `AdoptedExisting`; a validation failure there gets a distinct, non-terminal error.
- [ ] `integrator/src/lib.rs:333` - `is_ancestor` false-adopts when `head_commit` is trivially ancestral (empty implementer branch + prior crash), and `merge_commit_sha_for` then returns a DIFFERENT bundle's merge commit. - [ ] `integrator/src/lib.rs:235` - per-Plan-branch mode skips the dirty-tree guard (the comment claiming checkout protects it is false: non-conflicting dirty state is carried silently, then misclassified as a terminal conflict), and `integrate` parks HEAD on the integration branch forever. - [ ] `integrator/src/lib.rs:357` - every non-zero `git merge` exit is a "conflict" and terminally fails the Bundle - including deleted-branch, local-changes-overwritten, and ENOSPC. - [ ] `integrator/src/git.rs:224` - determinism contract ("same bundles + same base = same Tick SHA") is false: wall-clock author/committer timestamps and ambient identity make every run a different SHA. - [ ] `integrator/Cargo.toml:16` - the `worktree` dep is declared and entirely unused; merged bundle branches are never deleted (vision.md:137 claims the integrator deletes them post-Tick; only the restart sweep does). - [ ] `integrator/src/lib.rs:458` - multi-bundle crash mid-way through the per-Bundle `Merged` loop is unrecoverable (full-slice re-entry trips `BundleNotAccepted{Merged}`; subset re-entry defeats DuplicateTick keying and double-Ticks). - [ ] `integrator/src/lib.rs:226` - branch resolution / `verify_branch` / dirty check all run BEFORE `git_lock` (TOCTOU vs a concurrent integrate). Move inside the guard.
- [ ] `integrator/src/validation.rs:31,69` - zero instrumentation on the validation runner (a wedged command shows nothing), and output truncation keeps the HEAD 64 KiB when cargo puts failures at the tail. ## Alternatives Considered

### Alternative 1: Fix only criticals, defer the doc-truth and hygiene tails
- **Description:** Ship Phases 1-7; batch the rest "as touched."
- **Pros:** Faster to the high-value fixes.
- **Cons:** The doc-truth class IS a critical here: loopr is built by agents reading these docs; every vision lie becomes the next generation of wired-but-broken code. "As touched" is how the drift accumulated.
- **Why not chosen:** No-deferments is the operating rule; every finding gets a phase.

### Alternative 2: Implement the vision's missing subsystems (budgets, tiers, panic posture) as standalone feature docs instead of remediation phases
- **Description:** Treat vapor findings as new features, each with its own design doc.
- **Pros:** Cleaner per-feature review.
- **Cons:** They are not new designs - the vision already specifies each in detail; the gap is implementation, and the doc-vs-code contradiction is itself the defect. Splitting defers the lie.
- **Why not chosen:** The vision text is the design doc; these phases implement it (or amend it where the decision is to descope).

### Alternative 3: Soften the docs to match the code everywhere (amend-only, no implementation)
- **Description:** Resolve every contract divergence by editing the doc.
- **Pros:** Cheapest possible reconciliation.
- **Cons:** Some claims are load-bearing safety properties (panic posture, budgets, OCC, scope enforcement) whose absence is the bug, not the doc.
- **Why not chosen:** Decided per-item above: implement where the property protects the system (panic posture, budgets, OCC, containment, trailers); amend where the claim was aspiration (SSE streaming, `DecomposeStrategy`, `RetryStrategy` traits, config.yml seeding, CLI config flags).

## Technical Considerations

### Dependencies

No new external runtime deps. Internal edges change: integrator actually uses its declared `worktree` dep (branch deletion); context drops `store`/`telemetry`, keeps `llm` (docs amend); decomposer drops `store`; llm drops `domain`. All shared deps hoist to `[workspace.dependencies]`.

### Performance

Strictly improvements or neutral: JoinSet reaping bounds memory; the WorkFanout LRU bounds fds; per-pattern excludes append is O(patterns); OCC adds one `get` per Plan update (Works/Bundles already pay it). The bwrap wrap on Bash adds ~ms per invocation - the lane's 30s+ timeouts dwarf it.

### Security

Phase 5 is the security phase: denylist recursion/normalization/structural-rm, Bash filesystem containment, prompt-injection fencing, scope validation + rendering, path-join validation in telemetry, worktree guard rails. None change the threat model; they make the implemented model hold - the same posture as second-brain's Phase 5.

### Testing Strategy

Every fix in Phases 1-10 lands with a regression test in the same commit; TDD where the bug is reproducible first (the truncate panic, the denylist bypasses, the fence escape, the no-commit bundle, the same-ms OCC defeat are all of this shape). Phase 11 closes the remaining gaps. `otto ci` gates every phase; the telemetry clippy warning (Phase 9) gets fixed first since CI is `-D warnings`.

### Rollout Plan

See "Rollout" above; all local to the `v5` branch, no deployment surface beyond `cargo install` for local E2E runs.
